## 1. Executive Summary

This report documents the architectural design, implementation, and automated verification of **v1.4.0** of the **Adhan & Prayer Times** application.

This release introduces two major features:
1. **Daylight Saving Time / Standard Time System Control:**
   - **Automatic (Recommended):** Tracks host operating system timezone and system clock rules.
   - **Daylight Saving Time (Summer Time):** Enforces +1 hour offset if the host OS clock/timezone does not apply daylight saving time, while actively preventing double-offsetting when the OS already observes DST.
   - **Standard Time (Winter Time):** Reverts to standard astronomical time without daylight saving adjustments.
2. **12-Hour / 24-Hour Clock Format Control:**
   - Adds user-selectable time presentation (`12-Hour (AM/PM)` and `24-Hour`).
   - Strictly decoupled from the underlying `DateTime` calculations and OS alarm scheduling.

All existing systems—including Windows Task Scheduler (`schtasks`) synchronization, Android `AlarmManager` background alarms, auto-update mechanisms, and multi-city prayer calculation matrices—were preserved without regression.

## 2. Technical Investigation & Double-Offset Prevention

### Forensic Problem Analysis
The astronomical calculation engine (`package:adhan`) calculates prayer moments in UTC astronomical coordinates and then unconditionally calls `.toLocal()` on the resulting Dart `DateTime`.
- Dart's `.toLocal()` uses the host operating system's current timezone offset and OS-level DST state.
- **The Double-Offset Risk:** If a user is in an area observing DST (e.g. Egypt summer time UTC+3) and their OS clock is already set to UTC+3, naively adding +60 minutes in "Daylight Saving Time" mode would shift prayer times by +120 minutes (+2 hours), making all prayers an hour late.

### The Solution: `TimeSystemResolver`
We designed a domain service `TimeSystemResolver` that checks whether the local host OS is already observing DST on the target date:
```dart
static Duration calculateAdjustment({
  required TimeSystemMode mode,
  required DateTime date,
}) {
  switch (mode) {
    case TimeSystemMode.automatic:
      return Duration.zero;

    case TimeSystemMode.daylightSaving:
      // If OS is already observing DST, return Duration.zero to prevent double-offsetting.
      // If OS is in standard time, add +1 hour.
      return isSystemObservingDst(date) ? Duration.zero : const Duration(hours: 1);

    case TimeSystemMode.standard:
      // If OS is observing DST, subtract 1 hour to revert to standard time.
      // If OS is in standard time, return Duration.zero.
      return isSystemObservingDst(date) ? const Duration(hours: -1) : Duration.zero;
  }
}
```

## 3. Clock Formatting Architecture (12/24-Hour Decoupling)

To prevent clock format changes from triggering unwanted schedule reconciliation or modifying the underlying timing values:
- Created `AppTimeFormatter`: A centralized, direct time formatting utility.
- Supports 24-hour (`HH:mm`) and 12-hour (`h:mm a` or `h:mm ص/م` in Arabic).
- `ClockFormat` is pure presentation state: toggling between 12h and 24h updates widgets (`PrayerCard`, `NextPrayerHeroCard`) instantly via `BlocBuilder` without invoking `reconcileSchedules()`.

## 6. Scheduling Synchronization

### Windows Task Scheduler (`schtasks`)
- When `TimeSystemMode` changes:
  1. `DailyPrayerTimes` is recalculated with the compensatory offset.
  2. `AdhanSchedulerServiceImpl._reconcileWindowsTasks()` receives updated `ScheduledPrayerAlarm` instances.
  3. Desired tasks are re-registered with new `/st HH:mm` times via `schtasks /create /f`.
  4. Obsolete tasks are cleaned up via `schtasks /delete /f`.
  5. Verified via `test/live_multi_task_sync_test.dart` (**PASS**).

### Android AlarmManager
- When `TimeSystemMode` changes:
  1. Updated `timestampMillis` values are computed.
  2. Sent over MethodChannel `scheduleAlarms` to `MainActivity.kt`.
  3. `AlarmManager.setExactAndAllowWhileIdle` replaces pending intents.
  4. Cached in `flutter.cached_scheduled_alarms` for reboot persistence via `BootReceiver.kt`.
